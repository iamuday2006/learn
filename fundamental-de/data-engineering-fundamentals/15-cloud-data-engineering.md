# 15 — Cloud Data Engineering

Cloud data engineering uses managed services to reduce infrastructure burden and scale systems more effectively.

## Core cloud concepts
- Compute
- Storage
- Databases
- Object storage
- Networking
- IAM
- Managed services
- Serverless
- Scalability
- Availability
- Cost optimization

## AWS examples
- S3: object storage
- Glue: integration and ETL support
- EMR: managed Spark clusters
- Redshift: warehouse
- Kinesis: streaming ingestion

## Azure examples
- ADLS: data lake storage
- Data Factory: orchestration and integration
- Synapse: analytics platform
- Databricks: lakehouse and Spark processing

## GCP examples
- GCS: object storage
- Dataflow: streaming and batch processing
- BigQuery: warehouse
- Pub/Sub: messaging

## Key idea
Do not memorize only the services; understand what problem each category solves.

## Must Know
- Compute, storage, IAM, networking, serverless
- Cloud storage vs warehouse vs compute
- Managed services and cost trade-offs

## Good to Know
- Cloud-native ingestion patterns
- Scalability and availability design

## Advanced
- Multi-region patterns
- FinOps and platform design

## Interview Questions
1. Why do organizations move data engineering to the cloud?
2. What is the difference between object storage and a warehouse?
3. Why are managed services useful?
4. What problem does serverless solve?
5. How do you think about cost optimization in a cloud platform?
